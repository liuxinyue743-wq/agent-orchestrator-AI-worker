# Codex 项目规则

本文件只保存需要在每次任务中持续生效的规则。开始任何非简单任务前，先阅读：

1. `docs/PROJECT.md`；
2. `PLANS.md`；
3. 与当前任务直接相关的代码和测试；
4. 当前分支与 `git status`。

## 一、核心原则

- 遵循“如无必要，勿增实体”。
- 能由 AO 复用的能力不重复实现。
- 能由普通确定性程序完成的判断，不新增 LLM Agent。
- 不为未来可能需求提前增加 Agent、服务、框架、数据库、队列、抽象层或配置系统。
- 每次只完成当前任务明确要求的最小完整改动，不进行无关重构。

## 二、不可破坏的架构约束

- 项目级控制权只属于一个 Planner / Orchestrator。
- Worker 只执行边界清晰的编码任务，不负责项目级重规划。
- Auditor 只读：只能分析证据并返回结论，不能直接改代码、创建或停止 Worker、调整优先级或修改计划。
- 重复错误、超时、测试状态、依赖环、预算等确定性检查由普通程序完成。
- 每次 Auditor 结论必须返回 Planner，由 Planner 决定继续、局部修复、重规划或人工介入。
- 所有任务分别通过后，项目仍必须经过 Integration Gate 才能判定完成。
- MVP 优先验证 Codex Worker，最多并行两个 Worker；其他编码智能体后置。

## 三、AO 集成规则

- 在使用某个 AO 接口、事件或状态前，必须从锁定版本的源码或官方文档中确认其真实存在。
- 不得凭名称或设想虚构 AO API。
- 若 AO 已具备某项能力，应直接复用；只有确认无法满足需求后，才考虑外部 Adapter、扩展或最小 fork。
- 遇到未确认的 AO 行为时，先记录证据和待决问题，不得直接写正式实现绕过验证。

## 四、工作方式

对非简单任务：

1. 明确目标、范围和验收条件；
2. 检查相关文件，说明关键假设；
3. 给出简短实施计划；
4. 完成最小完整改动；
5. 增补或更新必要测试；
6. 运行仓库中真实存在的验证命令；
7. 检查最终 diff 是否越界或违反架构约束；
8. 仅在设计、已验证事实或当前计划发生变化时更新项目文档。

以下情况必须停止并说明，不能自行猜测：

- 当前任务与 `docs/PROJECT.md` 冲突；
- AO 集成点无法验证；
- 必须新增生产依赖、服务或破坏性迁移；
- 必须改变验收标准才能完成；
- 需要产品范围或比赛策略决策。

## 五、Git 与安全

- 只在当前任务分支工作，不直接修改或推送 `main`。
- 未经当前任务明确要求，不提交、不推送、不改写 Git 历史。
- 不使用破坏性 Git 命令，除非得到明确授权。
- 不提交密钥、令牌、`.env`、本机路径或机器专属配置。
- 一个提交只对应一个边界清晰的任务。

## 六、完成标准

任务只有在以下条件同时满足时才算完成：

- 明确的验收条件已经满足；
- 必要测试已添加或更新；
- 相关测试、格式检查、静态检查和构建均通过；
- 最终 diff 没有无关改动；
- 没有破坏架构约束；
- 未验证事项和剩余风险已明确列出。

测试通过不等于目标完成；不得通过削弱测试来让错误实现通过。

## 七、文档边界

- `AGENTS.md`：长期稳定的 Codex 工作规则；
- `docs/PROJECT.md`：项目目标、边界和架构；
- `PLANS.md`：当前里程碑和实施状态；
- 单次 Codex 提示词、聊天记录、临时审计意见：不写入仓库。

## 八、当前命令

项目使用 Python 3.11+。以下命令已在 Windows 的项目根目录中通过实际验证：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[test]"
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m compileall -q src
.\.venv\Scripts\python.exe -m pip check
```

当前运行依赖仅 `httpx`，测试依赖仅 `pytest`。

## 九、任务结束时的报告

任务结束时简要报告：

1. 完成了什么；
2. 修改了哪些文件；
3. 运行了哪些验证及结果；
4. 验收条件是否满足；
5. 仍有哪些假设、未验证点和风险。
